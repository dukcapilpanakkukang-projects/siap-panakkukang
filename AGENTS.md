# AGENTS.md — SIAP Panakkukang

React 19 + Vite + React Router 7 + Tailwind 3 + Zustand + Supabase. Staff-only queue-calling + Display TV for Kecamatan Panakkukang. Roles are only `ADMIN`/`PETUGAS` — no loket concept in auth, no `WARGA` role.

> `README.md` / `prd.md` are stale — trust code + this file. Stale claims: 3 services (now 5), Vercel deploy (now GitHub Pages), Realtime + Replication setup (now polling), `PREFIX-001` (now `PREFIX-N`, no padding). Public warga pages (`/ambil-antrean`, `/information`, `/ikd`) were deleted — no warga UI remains.

## Commands

- `npm install` → `npm run dev` (http://localhost:5173). `npm run build` → `dist/` (`npm run preview` to check).
- `npm run lint` is oxlint, warnings-only expected. No tests, typecheck, or formatter. Plain `.js/.jsx` — don't add TypeScript.
- Deploy: GitHub Pages via `.github/workflows/deploy.yml` (push to `main`, secrets `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`; copies `dist/index.html` → `dist/404.html` for SPA fallback). `vite.config.js` sets `base: '/siap-panakkukang/'` and `main.jsx` sets `BrowserRouter basename={import.meta.env.BASE_URL}` — internal new-tab links must use `<Link to="/display">`, never `<a href="/display">`, or the basename is bypassed and it 404s. Public-asset URLs must use `` `${import.meta.env.BASE_URL}...` ``, never leading `/` (logos in `layouts.jsx`, audio in `hooks.js`).
- UI: `GovLogos` from `layouts.jsx`; theme navy `#0b1220` + `orange-600`; reuse `btn-primary`/`card`/`input`/`badge` from `index.css`.

## Dual-mode data (biggest gotcha)

- `src/lib/supabase.js`: `isSupabaseConfigured = Boolean(URL && ANON_KEY)`. Empty/missing `.env` → **demo mode** (localStorage), not an error. No `.env.example` — edit `.env` directly, restart dev server. `.env` is gitignored; deploy injects vars from GitHub Secrets.
- Every service in `src/services/` branches on `isSupabaseConfigured`. **New data access must keep both branches** — never import `supabase` in components/pages.
- Demo keys: `siap_queues`, `siap_services_v2` (note `v2`), `siap_session`, `siap_users`, `siap_profile_overrides` (demo built-in name/password edits, applied in `login`/`getUsers`), `siap_requirements` / `siap_information` / `siap_announcements` / `siap_ikd`, `siap_kk_announcements`, `siap_broadcasts`, `siap_display_images`, `siap_rest`, `siap_reset_at` (round marker), `siap_call_lock` (`{at, by}` 30s cooldown — see Queues), `siap_tts` / `siap_volume`, `siap_last_call` / `siap_last_kk` / `siap_last_bc` (Display TTS dedup). Queue writes dispatch `siap:queues-changed`, master writes dispatch `siap:master-changed` (+ `storage` cross-tab) — dispatch the matching event after every local write. `withMissingSeeds()` in `masterService.js` appends new `SEED_SERVICES` without wiping admin edits. `getServices()` returns `is_active` only — the admin Services page alone uses `getAllServices()`.
- Polling, not Realtime: each page runs its own `setInterval(refresh, 3000)` + `siap:*-changed`/`storage` listeners. The shared `useRealtimeQueues` hook in `hooks.js` exists but is currently unused — no Replication setup needed.
- Prod DB: run `supabase/schema.sql` in SQL Editor — creates tables, RPCs, RLS, seeds, **and** public `display-images` bucket + Storage policies (without it, admin upload fails with RLS violation). Staff mutations call `assertSupabaseSession()` first; `PGRST116` ("Cannot coerce…", i.e. RLS silently denied) maps to a relogin message via `friendlySupabaseError()`.
- Timezone (proven outage): Supabase runs UTC, browsers run WITA (+8). `queue_date` is ALWAYS browser-local `todayKey()` — both RPCs take explicit `p_queue_date` (never DB `current_date`), and queue read/insert RLS policies use a ±1-day window. Otherwise 00:00–08:00 WITA writes vanish from dashboard/Display. After changing an RPC signature, `DROP FUNCTION` old+new sigs first (`CREATE OR REPLACE` rejects signature changes) and re-apply grants.

## Routes / auth

- `src/routes/AppRoutes.jsx`: `/` → `/login` (no public landing). `Login.jsx` has its own chrome (don't wrap it). Staff pages wrap in `DashboardLayout` (`layouts.jsx`) via `AdminShell` / `petugasMenu`. No `PublicLayout`.
- `/display` requires `PETUGAS`/`ADMIN` login — TV logs in once as petugas. Linked only via sidebar quickLinks ("Monitor Antrean", `external`, new tab).
- Demo: `admin@panakkukang.go.id`/`admin123`, `petugas1@panakkukang.go.id`/`petugas123`. Zustand `authStore.js` hydrates from `siap_session`. `counter_id`/`counter_name` are nulled compat fields — ignore them. No self-signup. `App.jsx` listens for Supabase `SIGNED_OUT` and force-clears the app session so a dead login redirects to `/login` instead of failing every mutation.
- Prod `createUser` creates the Auth user via client `signUp` (no Edge Function/service_role in this repo — it's the only client-side way), then inserts the `profiles` row with the returned UID; the admin session is saved before and restored after (in `finally`) because signUp without email-confirmation overwrites the local session and would otherwise log the admin out. If project email-confirmation is ON, new users must click the verification link before login. Demo custom users store their password in `siap_users` (pre-fix entries without password still can't log in).
- Own-account edit via `updateMyAccount` (name + optional password; email/role read-only): prod password goes through `auth.updateUser`, name through RPC `update_own_name` (SECURITY DEFINER touching only `full_name` — petugas has no UPDATE policy on `profiles`, and an open one would allow role escalation via console; needs latest `schema.sql` re-run, `42883` maps to that message, except ADMIN which falls back to a direct UPDATE that still passes its RLS policy). Never import the store into the service — the service already rewrites `siap_session`, the page calls `setUser`.
- Sidebar `NavLink` needs `end` (`DashboardNavItem`) or `/admin` stays highlighted on all `/admin/*`.

## Queues (`queueService.js` + `Queue.jsx`)

- Numbers are `PREFIX-N` via `makeQueueNumber` (`utils/date.js`); day key via `todayKey()`. 5 services in `constants.js` `SEED_SERVICES` (KTP, REKAM, IKD, KKO = KK Online Lontara+, KKB = KK Biasa). Statuses `WAITING → CALLED → SERVING → COMPLETED` + `SKIPPED`.
- Prod **must** use RPCs: `take_queue_number` (transactional, per-service `daily_quota`, granted to `anon`) and `call_direct_number` (SECURITY DEFINER, granted to `authenticated` only; direct `CALLED` inserts are rejected by RLS — fallback to direct insert only on missing function, code `42883`). `takeQueue` is dead code (no UI imports it) — new queues enter only via petugas coupon flow (`callDirect`/`callDirectMany`).
- Coupon workflow is free-order: `callDirect` creates the exact coupon number if missing, else recalls; gaps/skips allowed, no sequential guard. `callDirectMany` parses `5,6,7` / `5-8` via `parseQueueNumbers` (max `MAX_BATCH_CALL = 10`, sorted ascending) with one shared `called_at` — Display groups same-`called_at` CALLED rows as companions. Quota via `quotaFor()` (default 50, IKD 100, overridable via `daily_quota`). Progress bars count rows issued after today's last reset, while RPC quota counts ALL today's rows — don't "unify" them or reset would mint fresh quota.
- Call-text helpers in `constants.js` are pattern-based (survive admin prefix variants) — use them instead of hardcoding: `isLoketService()`/`callDestination()` (only `KK*` → loket, rest → Ruang Operator), `isNameCallService()` (REKAM is name-only — the call modal hides the number field and auto-assigns next sequence behind the scenes; Display card shows the serving name big, TTS says "Panggilan atas nama …"), `isSingleCallService()` (KTP & REKAM reject multi-number).
- Berikutnya auto-advance (`finishAndCallNext`): marks ALL active numbers of the batch COMPLETED at once (no Selesai button — the card button opens a confirm popup with an **optional name** field; empty = unnamed, IKD hides the field), then `callDirect`s (highest batch `sequence`)+1 and selects it. Batch chips are display-only. `SKIPPED` comes only from **Lewati & panggil** or `resetToday()`. `recallTarget()` re-CALLEs the whole batch with one shared `called_at` to keep Display grouping. Quota-exhausted still finishes the batch but skips the advance.
- Anti-menumpuk guard (`handleDirect`): a NEW number while `CALLED`/`SERVING` exist shows a confirm box (**Selesaikan & panggil** / **Lewati & panggil**) that finishes actives first. Re-calling already-active numbers (all requested ⊆ active, e.g. via chip) skips confirmation; idle batch (`5,6,7` for IKD/KKO/KKB) still allowed. Don't loosen without approval — a pile-up of a dozen actives (KTP-13..KTP-22) was a fixed bug.
- 30s call lock (`markCallLock`/`callLockRemaining` in `utils/queue.js`, `siap_call_lock = {at, by}`): every successful call stamps the lock; ANY new call within `CALL_LOCK_SECONDS` (a new TTS sequence cancels the old one), including from the same tab, is rejected with a "coba lagi ±N detik" notice. Remaining = max of instant localStorage lock (same-browser) and newest `called_at` among `CALLED`/`SERVING` rows (cross-device via 3s polling). Covers ALL announcement kinds both ways: KK/broadcast `created_at` counts as lock time, and `handleKK`/`handleBroadcast` check the lock + stamp it on success. Checked in `handleDirect` (skipped once Selesaikan/Lewati is confirmed), `confirmNext`, and `recallTarget`. Lock expires by timestamp (no permanent jam); name edits preserve `called_at` so they don't trip it.
- "SUDAH DIPANGGIL" chips list today's `CALLED`/`SERVING`/`COMPLETED` (not `SKIPPED`) **filtered to the current round** — `created_at`/`called_at`/`updated_at >=` round marker (same marker as the quota bars). The marker is the newest of the server marker (`display_contents key='reset'` via `getServerResetAt`, needs latest `schema.sql` re-run) and local `siap_reset_at` — required because `resetToday()` leaves `COMPLETED` rows untouched AND a local-only marker doesn't reach other devices. `resetToday()` never deletes — marks actives `SKIPPED` so History survives — upserts the server marker too and returns its ISO timestamp.
- Services can't be hard-deleted with queue rows (`queues.service_id on delete restrict`): Hapus checks `getServiceQueueInfo()` first (counts **all** dates, while History defaults to today) and confirms permanent delete including history (`deleteServiceWithHistory`); `deleteService` falls back to `is_active=false` on FK error `23503`.
- Three announcement channels — don't confuse: `announcements` = bottom ticker; `kk_announcements` (`callKKCase`/`getLatestKK`, BR-09, no number) and `broadcasts` (`sendBroadcast`/`getLatestBroadcast`, spontaneous) = ~20-sec banner + audio each.
- Petugas UX: never `alert()` in call flows — errors/success go through in-app `flash()` banner (`errText()` maps timeouts), every mutation wrapped in the local `withTimeout(20s)` helper (each petugas page defines its own — copy the pattern for new pages); `window.confirm` only for reset. Modal-path errors render inline (`specErr`/`nextErr`/`kkErr`/`bcErr` — `flash()` sits behind the modal overlay). The Panggil Nomor "Panggil Sekarang" button must stay `type="button" + onClick={handleDirect}` — as `type="submit"` it was field-proven to never fire.

## TTS / display

- TTS `useSpeech()` (`hooks.js`): `id-ID`, toggle in `siap_tts`, volume in `siap_volume` (max 1.0 — browser cap). Opening sound → announcement 2x → closing sound. A new announcement cancels speech AND stops the previous jingle `<audio>` (`stopJingle` — `cancel()` alone doesn't stop audio elements). Closing plays only if its generation is still alive AND speech is verified silent — never overlapping. Muting mid-announcement kills everything silently. Audio filenames contain a space (`opening sound.mp3`) — don't rename without updating `hooks.js`.
- Display starts silent until first user gesture (autoplay policy — unlock button calls `wake()`); dedup via `siap_last_*` so reopening doesn't re-announce. KK/broadcast banners show only if `created_at` is <20s old.
- Display slideshow (`Display.jsx`): one slide per image category; header text only on staff-photo slides, never overlaid on images; the `info` slide is just the empty-state fallback. Manual dots/arrows; auto-slide continues from the chosen slide.
- Uploads must pass the real `File` to `uploadDisplayImage`/`uploadRestImage` (Storage upload in prod); base64-only silently takes the demo branch. Map URLs via `imageUrl()` — never return raw `file_path`. Title/description edits go through `updateDisplayImage` (no re-upload).
- Rest mode (`displayService.js` `getRestConfig`/`saveRestConfig`/`uploadRestImage`, `isRestNow()`/`activeRestSchedule()` in `utils/date.js`): ONE `display_contents` row `key='rest'` with JSON `{enabled, start, end, image, friday: {...}}` — no migration needed. Config lives on the dedicated **`/petugas/rest` page** (linked from both petugas and admin menus), with separate Harian + Jumat tabs — an empty Friday image falls back to the daily schedule. Prod images go to Storage `display-images/rest/...` (not `display_images`, to dodge the category check); demo keeps base64 in `siap_rest`. Needs latest `schema.sql` re-run (`rest/*` Storage + `display_contents key='rest'` writable by `PETUGAS`; other display content stays ADMIN-only). Display swaps the left slideshow for the rest image during the window (overnight wrap supported, start inclusive/end exclusive) while queue cards + ticker keep running.
- Dead code: `src/pages/admin/Information.jsx` has no route (and its `masterService` information/IKD getters have no live reader — the Display ticker uses `announcements`). Don't wire it up unless asked.
